# شکارچی قیمت، دسته‌بندی واحد، سوییچ پلتفرم، محصول اشتراکی

> تاریخ: ۱۴۰۵/۰۶/۰۶ (۲۰۲۶-۰۸-۲۸)
> وضعیت: **فقط مستند** — تا تأیید کارفرما کدنویسی شروع نمی‌شود
> وابسته به: `docs/multi-platform-sheypoor-ring.md` (اتصال شیپور و رینگ)
> نسخه فعلی برنامه: ۲.۱.۲۵ — فقط دیوار، شکار قیمت هنوز «بازه دستی + تیک VIP» است نه شکارچی واقعی

## ۰) خلاصه برای تصمیم

چهار خواسته این سند:

1. بعد از لاگین، **آگهی و شماره** از هر پلتفرم فعال گرفته شود.
2. **قیمت واقعاً تشخیص داده شود** و اگر فیلتر قیمت باشد، فقط همان‌ها بمانند.
3. **یک درخت دسته** در پنل بماند (دسته جدا برای شیپور/رینگ نه) — فقط کامل شود.
4. **هر پلتفرم روشن/خاموش** شود.
5. بخش «قیمت مناسب / خیلی مناسب / ارزون» از فیلتر ساده به **شکارچی حرفه‌ای** تبدیل شود و کل محصول به‌صورت **اشتراک تجاری** قابل فروش باشد.

| موضوع | الان | هدف بعد از تأیید |
|---|---|---|
| گرفتن آگهی | فقط دیوار | دیوار + شیپور + رینگ، فقط پلتفرم‌های روشن |
| گرفتن شماره | فقط دیوار، بعد از لاگین | همان، per-platform، صف اولویت برای شکار |
| تشخیص قیمت | تومان از متن/JSON؛ ریال دیوار گاهی اشتباه | نرمال تومان + نوع قیمت (نقد/توافقی/اقساط/معاوضه) |
| فیلتر بازه | min–max میلیون تومان؛ بدون قیمت = رد | همان + حالت شکارچی نسبت به بازار |
| VIP | تیک روی پایش؛ هر آگهی داخل بازه «ویژه» است | سه سطح: مناسب / خیلی مناسب / مشکوک |
| دسته | ~۳۵ مورد دیوار، ناقص | یک درخت کامل‌تر؛ اسلاگ هر سایت پشت صحنه |
| پلتفرم | فقط دیوار | سه سوئیچ سراسری دیوار/شیپور/رینگ |

نظر کوتاه محصول: **نیاز جامعه واقعی است** (در تورم، فرصت ارزان ظرف چند دقیقه می‌رود). چیزی که الان «VIP» نام دارد شکارچی نیست؛ فیلتر بودجه است. اگر بخواهیم اشتراک بفروشیم، ارزش باید این باشد: *زودتر از بقیه، روی سه سایت، با تشخیص «ارزون واقعی» نه هر آگهی داخل بازه.*

## ۱) آنچه امروز در کد هست (صادقانه)

تب کلمات:

- دسته دیوار
- کلمه (اختیاری)
- یک شهر
- حداقل / حداکثر قیمت به **میلیون تومان**
- تیک «هشدار ویژه (VIP)» → تلگرام فوری + صف شماره

منطق `pricing.py` / `matching.consider_new_lead`:

- اگر بازه خالی باشد همه قبول‌اند.
- اگر بازه باشد و قیمت خوانده نشود → **رد**.
- «توافقی» قیمت ندارد → با فیلتر فعال **گم می‌شود**.
- VIP فقط یک پرچم روی همان پایش است؛ برنامه نمی‌داند این قیمت نسبت به بازار ارزان است یا گران.

نمونه زنده شیپور (۱۴۰۵/۰۶/۰۶) که شکارچی باید بفهمد:

| آگهی | قیمت روی کارت | معنی برای شکارچی |
|---|---|---|
| پراید خوش قیمت | ۴۷۵٬۰۰۰٬۰۰۰ | عدد نقد، قابل مقایسه |
| پراید ۱۳۱ | قیمت توافقی | بدون عدد — شکار نشود مگر کاربر توافقی را بخواهد |
| سیم‌کارت رند | ۳٬۸۰۰٬۰۰۰٬۰۰۰ | عدد درست اما کالای دیگر؛ اگر پایش «موبایل» باشد نویز است |
| نوکیا ارزان‌فروشی فروشگاه | ۴۰۰٬۰۰۰ | مشکوک / عمده / کلیک‌بیت |
| «خریدار گوشی شکسته» | توافقی | **خریدار است نه فروشنده** — هرگز شکار نشود |

نتیجه: بدون تشخیص نوع آگهی، «ارزون» پر از زباله می‌شود و اشتراک نمی‌فروشد.

## ۲) گرفتن آگهی و شماره (هسته محصول)

این بخش از لاگین جدا نیست؛ لاگین فقط کلید شماره است.

```
پایش فعال
   │
   ├─ پلتفرم خاموش؟ → رد
   ├─ جستجو (بدون لاگین برای دیوار/شیپور؛ رینگ از Chromium)
   ├─ پارس: عنوان، لینک، شهر، قیمت، نوع قیمت، فروشگاه؟
   ├─ تطبیق کلمه + دسته + شهر
   ├─ فیلتر/شکار قیمت
   ├─ ذخیره سرنخ  (کلید: پلتفرم + شناسه)
   │
   └─ صف شماره (اولویت با شکار)
         ├─ سشن همان پلتفرم در همان پروفایل
         ├─ پیدا شد → ذخیره + پیامک اختیاری + هشدار
         └─ مخفی / فقط چت → لیست چت نیمه‌خودکار
```

قواعد ثابت:

- Discovery بدون لاگین برای دیوار و شیپور شدنی است (HTML عمومی).
- رینگ در فاز اول از همان پروفایل Chromium.
- شماره همیشه بعد از لاگین همان سایت.
- اگر پلتفرمی برای آن اکانت لاگین نباشد، **فقط همان پلتفرم** برای آن اکانت می‌ایستد.
- چت انبوه خودکار اضافه نمی‌شود.

صف شماره پیشنهادی:

1. شکار «خیلی مناسب» بدون شماره
2. شکار «مناسب»
3. VIP بازه دستی
4. بقیه سرنخ‌ها (جدیدترین)

## ۳) تشخیص قیمت — باید درست کار کند وگرنه شکارچی دروغ می‌گوید

واحد داخلی همیشه **تومان** است. پنل مثل الان میلیون تومان می‌گیرد.

### ۳.۱ منابع قیمت per-platform

| منبع | دیوار | شیپور | رینگ |
|---|---|---|---|
| روی کارت لیست | subtitle / JSON (اغلب ریال) | تومان با رقم فارسی، یا «توافقی» | بعد از جزئیات / DOM |
| روی صفحه آگهی | ویجت قیمت | تومان واضح | بعد از لاگین هم هست |
| بدون عدد | توافقی / نامشخص | «قیمتتوافقی» | مشابه |

دیوار: اسکیما غالباً **ریال** است؛ UI **تومان**. کد فعلی HTML نزدیک توکن را `rial // 10` می‌کند. متن کارت با `parse_toman` تومان می‌ماند. اگر دو منبع قاطی شوند، قیمت ۱۰ برابر یا یک‌دهم می‌شود — برای شکارچی مرگبار است.

شیپور: روی کارت تومان است (نمونه زنده: `۴۴۰,۰۰۰,۰۰۰`، `۱۳,۰۰۰,۰۰۰`). «توافقی» جدا است. ریال دیده نشد.

رینگ: تا ضبط Flutter، قیمت از DOM همان پروفایل.

### ۳.۲ خروجی استاندارد هر آگهی (پیشنهاد داده)

```
price_toman: int | null
price_kind: cash | negotiable | installment | swap | buyer | free | unknown
price_confidence: high | medium | low
price_raw: متن اصلی
```

قواعد رد / نگه:

| حالت | فیلتر بازه روشن | شکارچی روشن |
|---|---|---|
| نقد با عدد معتبر | اگر داخل بازه | امتیاز نسبت به بازار |
| توافقی / نامشخص | رد (مثل الان) | رد، مگر تیک «توافقی را هم نگه دار» |
| اقساط | رد پیش‌فرض | رد مگر تیک اقساط |
| معاوضه | رد | رد |
| رایگان | رد از فیلتر قیمت | جدا (واگذاری) — شکار قیمت نیست |
| خریدار / می‌خرم / خریدار گوشی | همیشه رد | همیشه رد |
| عدد ۱ یا خیلی کوچک نسبت به دسته | رد | برچسب مشکوک، هشدار نده |
| فروشگاه / ویترین | قبول | امتیاز کمتر؛ تیک «فقط شخصی» حذفشان می‌کند |

### ۳.۳ دام‌های ایرانی که باید در پارس باشد

- ارقام فارسی/عربی، جداکننده `٬` و `,`
- «۴۵ میلیون» / «۱.۲ میلیارد» / «۴۵۰ هزار»
- ریال در برابر تومان (دیوار)
- «از ۵۰ میلیون» = کف، نه قیمت قطعی → confidence پایین
- قیمت اجاره ماهانه در برابر قیمت فروش (دسته املاک)
- سیم‌کارت رند چند میلیارد وسط دسته موبایل
- «تخفیفی» / «فوری» / «Ad تابلو شده» قیمت نیستند

تا این لایه درست نباشد، سطح «خیلی مناسب» معنی ندارد.

## ۴) دسته‌بندی: کامل شود، جدا نشود

خواسته: **یک انتخاب دسته در پنل**، مثل الان. شیپور و رینگ درخت جدا در UI نمی‌گیرند.

الان `categories.py` حدود ۳۵ مورد است. دیوار رسمی ~۱۸۰ دسته دارد. هدف فاز اول: **همه گروه‌های اصلی + زیردسته‌های پرکاربرد شکار/سرنخ** — نه ۱۸۰ خط که کسی اسکرول نکند.

پشت صحنه هر گره سه اسلاگ دارد: `divar` / `sheypoor` / `ring`. اگر اسلاگ رینگ هنوز ضبط نشده، آن گره روی رینگ به نزدیک‌ترین والد می‌رود یا آن پلتفرم برای آن پایش رد می‌شود (لاگ واضح).

### ۴.۱ درخت واحد پیشنهادی (کامل‌تر از الان)

اسلاگ ستون «کد» همان شناسه داخلی پنل است (ترجیحاً اسلاگ دیوار برای سازگاری داده فعلی).

گروه اصلی حتماً باشد. زیردسته فقط آنهایی که سرنخ یا شکار دارند:

- خدمات: `services` → شیپور `services` (آموزش، تعمیرات، نظافت، حمل، زیبایی، …)
- استخدام: `jobs` → `jobs` (زیردسته‌های شیپور زنده‌اند: راننده، فروشنده، نگهبان، …)
- شخصی: `personal` → `personal-stuff` (`fashion`, `jewelry-watch`, `health-beauty`, `babies-kids`)
- سرگرمی: `entertainment` → `sports-games-hobbies` (`bicycles`, `sporting-goods`, `book-stationery`, `musical-instruments`, `collectibles`)
- حیوانات: `animals` (+ گربه/سگ/پرنده) → شیپور زیر سرگرمی `animals-pet`
- صنعتی: `tools-materials-equipment` → `industrial-commercial`
- اجتماعی: `social-services`

رینگ: گروه‌های اعلام‌شده همان‌اند (املاک، نقلیه، خدمات، خانه، سرگرمی، استخدام، دیجیتال، لوازم فردی، صنعتی، اجتماعی). اسلاگ دقیق بعد از ضبط Flutter در همین درخت پر می‌شود — UI عوض نمی‌شود.

### ۴.۲ رفتار جستجو

کاربر «موبایل» را می‌زند:

- دیوار: `/s/{شهر}/mobile-phones?q=`
- شیپور: `/s/{شهر}/mobile-tablet?q=`
- رینگ: دسته معادل در اپ/وب

«همه دسته‌ها» + کلمه = جستجوی آزاد هر سایت روشن.
فقط دسته بدون کلمه = مرور کل دسته (رفتار فعلی `browse`).

دسته بدون اسلاگ در یک پلتفرم = آن پلتفرم برای آن پایش رد با دلیل در لاگ، نه کرش.

## ۵) روشن / خاموش کردن پلتفرم

یک سوئیچ سه‌تایی در تنظیمات (و تکرار کوچک روی داشبورد):

```
☑ دیوار     ☑ شیپور     ☑ رینگ
```

قواعد:

- پیش‌فرض بعد از اتصال: هر سه روشن.
- خاموش = آن سایت در آن نصب **اصلاً** جستجو و شماره‌گیری نمی‌شود (سهمیه و ریسک کمتر).
- اگر هر سه خاموش باشند اسکن شروع نمی‌شود، با پیام واضح.
- لاگین پروفایل مستقل است: می‌شود رینگ را خاموش کرد ولی سشن رینگ در پروفایل بماند.
- روی کارت پایش، سه نقطه رنگی کوچک: این پایش از کدام سایت‌ها تغذیه می‌شود (ارث از سوییچ سراسری).

فاز ۱: فقط سوییچ سراسری.  
فاز ۲ (اختیاری): تیک per-پایش اگر یک کلمه فقط روی دیوار لازم باشد. برای فروش اشتراک لازم نیست روز اول.

## ۶) شکارچی قیمت — نظر و طرح حرفه‌ای

### ۶.۱ مشکل محصول فعلی

VIP فعلی می‌گوید: «هر آگهی داخل بازه ۲۰ تا ۸۰ میلیون».

شکارچی باید بگوید: «این آیفون ۱۳ تهران **۳۲ میلیون** است؛ میانه بازار همین پایش **۴۸ میلیون** است؛ **۳۳٪ زیر بازار**؛ تازه ۲ دقیقه پیش.»

بدون میانه بازار، «ارزون» شعار است.

### ۶.۲ دو حالت روی همان فرم کلمات (UI شلوغ نشود)

**حالت الف — فیلتر بودجه (همان الان)**  
حداقل / حداکثر. مناسب کسی که بودجه دارد (مثلاً «پراید تا ۴۰۰ میلیون»).

**حالت ب — شکارچی (جدید، تیک)**  
بازه اختیاری است. برنامه از آگهی‌های اخیر همان (کلمه + دسته + شهر + پلتفرم‌های روشن) **میانه** می‌سازد و آگهی جدید را نسبت به میانه می‌سنجد.

پیشنهاد تیک‌ها روی همان کارت، بدون تب جدید:

- فیلتر بازه (مثل الان)
- شکارچی قیمت
- سطح هشدار: مناسب / خیلی مناسب (پیش‌فرض هر دو)
- رد کردن: توافقی، اقساط، فروشگاه، خریدار (پیش‌فرض همه رد به‌جز فروشگاه که اختیاری است)

### ۶.۳ امتیاز (Deal Score)

برای هر پایش، پنجره مثلاً ۷۲ ساعت یا حداقل ۳۰ آگهی نقد معتبر:

- `median` میانه تومان
- `p25` / `p75` برای پراکندگی
- اگر نمونه کمتر از حد → شکارچی «گرم نشده»؛ فقط فیلتر بازه کار می‌کند و در پنل نوشته می‌شود «هنوز بازار این پایش ساخته نشده»

امتیاز آگهی جدید:

```
discount_pct = (median - price) / median
```

| سطح | پیشنهاد پیش‌فرض | معنی برای کاربر |
|---|---|---|
| بازار | −۵٪ تا +۱۰٪ | معمولی — ذخیره بشود، هشدار ویژه نه |
| مناسب | ۱۰٪ تا ۲۲٪ زیر میانه | فرصت خوب |
| خیلی مناسب (ارزون) | بیش از ۲۲٪ زیر میانه | شکار — صدای پنل + تلگرام فوری + اول صف شماره |
| مشکوک | بیش از ۴۵٪ زیر میانه، یا قیمت خارج از عقل دسته | هشدار داده **نشود**؛ برچسب مشکوک برای بازبینی |

درصدها باید در تنظیمات قابل تغییر باشند (خودرو پراکنده‌تر از موبایل است). پیش‌فرض محافظه‌کارانه بهتر از آلارم الکی است؛ آلارم الکی اشتراک را می‌کشد.

### ۶.۴ ضد زباله — فرق شکارچی آماتور و حرفه‌ای

بدون این لیست، محصول تجاری نمی‌شود:

1. عنوان شامل «خریدار»، «می‌خرم»، «خرید نقد»، «خریدار گوشی» → حذف
2. توافقی / معاوضه / اقساط (قابل تیک)
3. قیمت ۱، ۱۱، ۱۱۱، ۱۰۰۰ نسبت به میانه دسته
4. آگهی فروشگاهی اگر «فقط شخصی» روشن باشد (لوگوی shop شیپور زنده است)
5. کلمه در عنوان نخورد ولی دسته خورده — برای شکارچی سخت‌گیر: عنوان باید مدل را داشته باشد (آیفون ۱۳ نه «گوشی اپل»)
6. تکراری بین دیوار و شیپور (عنوان نرمال + قیمت نزدیک) → یک شکار، دو لینک
7. آگهی قدیمی که تازه به صفحه اول آمده — اولویت با `لحظاتی پیش` / چند دقیقه
8. اختلاف ۱۰× با میانه = احتمالاً ریال/تومان؛ شکار نشود

### ۶.۵ هشدار شکار (جایگزین متن VIP فعلی)

```
شکار خیلی مناسب
پلتفرم: شیپور
شهر: تهران · دسته: موبایل
قیمت آگهی: ۳۲ میلیون
میانه ۳ روز: ۴۸ میلیون (−۳۳٪)
آگهی: آیفون ۱۳ پرو ۲۵۶
لینک: …
زمان کشف: ۱۴۰۵/۰۶/۰۶ ۱۲:۰۴:۱۹
شماره: (بعد از استخراج)
```

پنل: تگ رنگی مناسب / خیلی مناسب / مشکوک، ستون قیمت + درصد، فیلتر «فقط شکارها».

صدای فعلی VIP برای «خیلی مناسب» بماند؛ برای «مناسب» آرام‌تر.

### ۶.۶ آنچه عمداً در نسخه اول شکارچی نمی‌آید

- هوش مصنوعی تشخیص عکس (بعداً)
- قیمت جهانی دلار/طلا (مگر پایش طلا/سکه جدا)
- پیش‌بینی قیمت فردا
- خرید خودکار
- نمره «سلامت کالا»

نسخه اول: **سرعت + میانه + ضد زباله + سه سایت + شماره**. همین برای فروش اشتراک کافی است اگر آلارم دروغ ندهد.

### ۶.۷ پیشنهاد تجربه کاربری شکارچی

کاربر حرفه‌ای این را می‌خواهد:

1. پایش «آیفون ۱۳» / موبایل / تهران / شکارچی روشن / خیلی‌مناسب
2. مانیتور روشن
3. گوشی در جیب، تلگرام
4. زیر ۳۰–۹۰ ثانیه از انتشار آگهی، پیام با لینک و بعد شماره
5. اگر دیر برسد ارزش صفر است — پس Watcher شکار باید نسبت به پایش عادی **کوتاه‌تر** بتواند تیک بخورد (مثلاً ۶۰–۹۰ ثانیه فقط برای پایش‌های شکار، با RateLimiter جدا تا دیوار نشکند)

این فاصله کوتاه فقط روی پایش شکار، نه همه کلمات بازاریابی. وگرنه بلاک می‌شوید.

## ۷) محصول تجاری و فروش اشتراک

### ۷.۱ نیاز واقعی بازار (نه شعار)

در ایران بازار دست‌دوم به‌خاطر تورم و محدودیت واردات بزرگ است. سه شغل هر روز دیوار را «می‌نشینند»:

1. **نوسان‌گیر کالا** (موبایل، طلا، لپ‌تاپ، کنسول): ارزان می‌خرد، همان روز می‌فروشد.
2. **نمایشگاه / بنگاه / فروشگاه**: فایل ارزان‌تر از کف بازار.
3. **کسب‌وکار خدماتی**: سرنخ از آگهی (تدریس، تعمیرات، حمل) — محصول فعلی پیامک/چت.

رقیب امروز: یک نفر با دو گوشی که F5 می‌زند. محصول ما همان کار را روی سه سایت، با فیلتر قیمت واقعی، بدون خوابیدن پای مانیتور انجام می‌دهد.

دو خط محصول داخل یک برنامه (عمداً جدا فکر شود):

| خط | مشتری | ارزش | ریسک حقوقی/قوانین سایت |
|---|---|---|---|
| **شکارچی فرصت** | خریدار/نوسان‌گیر | زودتر دیدن ارزان | کمتر — شبیه جستجوی پیشرفته |
| **موتور سرنخ** | فروشنده/بازاریاب | شماره و پیام به آگهی‌دهنده | بیشتر — شرایط استفاده سایت‌ها + تبلیغات |

برای فروش اشتراک عمومی، **چهره محصول را شکارچی** بگذارید. موتور سرنخ بماند قابلیت پلن بالاتر، نه شعار صفحه فرود.

### ۷.۲ چرا اشتراک نه فروش یک‌باره فقط

- سایت‌ها HTML/API عوض می‌کنند → نگهداری مداوم
- سهمیه و بلاک یعنی پشتیبانی
- میانه بازار هر روز باید زنده بماند
- پلتفرم سوم (رینگ) تازه است و می‌شکند

لایسنس یک‌باره بدون به‌روزرسانی می‌میرد. مدل درست: **نصب ویندوز محلی (داده پیش مشتری) + اشتراک قابلیت/پشتیبانی.**

داده آگهی و شماره روی سیستم مشتری بماند (همین معماری فعلی). سرور شما لایسنس و به‌روزرسانی می‌دهد، نه دیتابیس شماره. این هم فروش را ساده‌تر می‌کند هم ریسک «فروش دیتابیس شماره» را کم.

### ۷.۳ بسته‌های پیشنهادی

اعداد تومان فقط جهت ساختار است؛ قیمت نهایی با شماست.

**آزمایش ۷ روزه**  
یک پلتفرم، ۲ پایش، بدون شماره، شکارچی با تأخیر. هدف: ببیند آلارم می‌آید.

**پلن شکارچی** — مشتری اصلی  
سه پلتفرم با سوییچ، شکارچی کامل، هشدار تلگرام/بله/روبیکا، گرفتن شماره، تا مثلاً ۸ پایش، ۱–۲ اکانت.

**پلن کسب‌وکار**  
همان + چند اکانت، پیامک ملی‌پیامک، سقف بالاتر، خروجی اکسل، قالب چت، پایش بیشتر.

**پلن نمایندگی / تیم**  
چند اپراتور، گزارش، چند شهر. وقتی تقاضای بنگاه/نمایشگاه آمد.

قفل پلن با سوییچ قابلیت، نه با ضعیف کردن دروغین جستجو:

| قابلیت | آزمایش | شکارچی | کسب‌وکار |
|---|---|---|---|
| دیوار | ✓ | ✓ | ✓ |
| شیپور + رینگ | — | ✓ | ✓ |
| شکارچی مناسب/ارزون | محدود | ✓ | ✓ |
| گرفتن شماره | — | ✓ | ✓ |
| پیامک خودکار | — | — | ✓ |
| چند اکانت Chromium | ۱ | ۲ | بیشتر |
| فاصله اسکن شکار | آهسته | تندتر | تندتر |

سوییچ پلتفرم در همه پلن‌ها هست؛ در آزمایش فقط دیوار روشن است.

### ۷.۴ صفحه فروش باید چه بگوید (و نگوید)

بگوید:

- سه سایت آگهی ایران، یک پنل
- فرصت ارزان را قبل از دیگران ببین
- قیمت را می‌فهمد؛ توافقی و خریدار را شکار نمی‌کند
- شماره وقتی خودت لاگین کرده باشی
- داده روی سیستم خودت است

نگوید:

- «اسپم همه آگهی‌دهندگان»
- «دور زدن کپچا»
- «دیتابیس شماره آماده»

اعتماد شکارچی به **دقت آلارم** است. یک هفته آلارم زباله = لغو اشتراک.

### ۷.۵ معیار سلامت محصول (برای خودتان)

هفتگی:

- درصد شکارهایی که کاربر روی لینک کلیک کرده
- درصد «مشکوک» به کل شکار
- زمان از انتشار آگهی تا هشدار (هدف: زیر ۲ دقیقه برای دیوار/شیپور روی IP ایران)
- نرخ بلاک اکانت

اگر کلیک پایین است، درصد «خیلی مناسب» را سخت‌تر کنید نه برعکس.

## ۸) ریسک حقوقی و عملی (کوتاه، لازم برای محصول پولی)

- خواندن آگهی عمومی ≠ مجوز استخراج انبوه شماره و پیام تبلیغاتی.
- شرایط استفاده دیوار/شیپور/رینگ دسترسی خودکار را نمی‌خواهند.
- پیامک تبلیغاتی بدون رضایت، مسیر ملی‌پیامک و قوانین تبلیغات را دارد.
- فروش اشتراک «شکارچی خرید» قابل دفاع‌تر از فروش «لیست شماره فروشنده» است.

پیشنهاد محصول پولی: پیش‌فرض شکارچی روشن، پیامک خودکار خاموش، چت نیمه‌خودکار.

## ۹) ترتیب بعد از «شروع کن» (هنوز اجرا نشود)

1. سوییچ پلتفرم + آداپتور (دیوار فعلی نشکند)
2. تشخیص قیمت استاندارد (نوع قیمت + تومان) روی دیوار و شیپور
3. درخت دسته کامل + نگاشت شیپور
4. گرفتن آگهی/شماره شیپور
5. شکارچی: میانه پایش + سطح مناسب/خیلی‌مناسب/مشکوک + ضد خریدار
6. اولویت صف شماره برای شکار
7. رینگ از Chromium
8. برچسب پلتفرم در سرنخ و تلگرام
9. (جدا) قفل پلن/لایسنس اگر اشتراک فروخته می‌شود

آزمایش آفلاین: قیمت توافقی، خریدار، ریال دیوار، تومان شیپور، بازه، میانه ساختگی.

## ۱۰) پیش‌فرض‌هایی که با «شروع کن» می‌روم مگر خلافش بگویید

1. یک درخت دسته؛ نگاشت پشت صحنه.
2. سه سوئیچ سراسری دیوار/شیپور/رینگ.
3. فیلتر بازه فعلی می‌ماند؛ شکارچی تیک جدا روی همان کارت.
4. پیش‌فرض شکارچی: توافقی/اقساط/خریدار رد؛ فروشگاه با امتیاز کمتر.
5. «خیلی مناسب» ≈ ۲۲٪ زیر میانه؛ «مشکوک» ≈ ۴۵٪+ بدون هشدار.
6. چهره فروش: شکار فرصت؛ سرنخ/پیامک در پلن بالاتر.
7. لایسنس ابری برای اشتراک؛ داده آگهی محلی.

تا اعلام شروع، کدی نوشته نمی‌شود.

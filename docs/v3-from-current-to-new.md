## ۰) درک متن: API رایگان چرخشی در برابر مدل داخل برنامه

سؤال: «رایگان از APIهای رایگان با چرخش استفاده کنیم بهتر نیست؟ مدل جدا دانلود نشود؛ با سورس یکی شود؛ خودت بگیر بگذار داخل.»

**نظر فنی: نه — برای این برنامه در ایران، API رایگان ابری موتور اصلی نشود.**

| | قاعده داخل سورس | مدل محلی ۱٫۵B (مثل Chromium) | API رایگان ابری با چرخش |
|---|---|---|---|
| هزینه ماهانه | صفر | صفر | صفر تا وقتی سهمیه بدهند |
| داخل گیت | بله — واژگان و پارس | خیر (۱٫۵ GB؛ سقف فایل گیت‌هاب ۱۰۰ MB) | کلیدها را نباید در گیت گذاشت |
| اینترنت ایران | لازم نیست | بعد از یک دانلود | اغلب فیلتر؛ VPN دیوار/شیپور را می‌شکند |
| سهمیه | ندارد | ندارد | Groq/Gemini/OpenRouter قطع و عوض می‌شوند |
| حریم پاسخ فروشنده | روی همان PC | روی همان PC | متن چت/پیامک می‌رود بیرون |
| پایداری محصول فروشی | بالا | بالا | پایین — فردا مدل رایگان حذف می‌شود |
| خلاف شرایط سرویس | — | لایسنس Apache مدل | چرخش کلید رایگان معمولاً سوءاستفاده حساب می‌شود |

پس «رایگان و داخل سورس» واقعی همان است که از روز اول باید باشد:

**لایه ۱ (همیشه، بدون دانلود): موتور قاعده داخل `pricing` / واژگان معیوب / جای‌نگهدار / خریدار.**  
این همان هوشمندی است که با کد فعلی یکی می‌شود. فایل جدا نمی‌خواهد.

**لایه ۲ (اختیاری، مثل Chromium): Qwen 1.5B GGUF یک‌بار در `%LOCALAPPDATA%\DivarMarketing\nlu-model\`.**  
داخل مخزن نمی‌آید — حجم و باینری. نصب‌کننده همان الگوی دانلود Chromium را دارد.

**لایه ۳ (اختیاری کاربر، نه چرخش مخفی): اگر مشتری **کلید خودش** را در تنظیمات گذاشت (مثلاً Gemini رایگان خودش)، برای جواب مبهم استفاده شود.**  
چرخش کلیدهای جمع‌آوری‌شده در برنامهٔ فروشی نه پایدار است نه درست.

مدل ۱٫۵ گیگ را **الان داخل ریپو نمی‌گذارم**: گیت را خراب می‌کند، کلون سنگین می‌شود، و شما هنوز «شروع کن» نگفته‌اید.

هسته شکار و ویژه **بدون هیچ مدلی** کار می‌کند. مدل فقط برای جملهٔ محاوره‌ای پاسخ است.

## ۱) نسخه فعلی ۲.۱.۲۵ چه دارد (صادقانه)

| بخش | وضعیت امروز |

| پیامک | خودکار ملی‌پیامک اگر تیک روشن |

| اعلان | تلگرام / بله / روبیکا با تیک |
| خروجی | CSV شماره‌دار / فقط‌چت |

## ۲) نسخه ۳ باید چه باشد — نقشه قابلیت

```
۲.۱.۲۵                          ۳.۰
فقط دیوار                  →  دیوار + شیپور + رینگ (سوییچ)
یک لاگین دیوار             →  همان پروفایل، سه تب OTP جدا
بازه + تیک VIP             →  فیلتر بودجه + شکارچی میانه بازار
قیمت خام                   →  نقد / توافقی / جای‌نگهدار / معیوب / خریدار
چت نیمه‌خودکار             →  چت خودکار با سقف، سه سایت
پیامک خودکار               →  همان + خواندن پاسخ صندوق
بدون فهم جواب              →  قاعده داخل سورس + مدل محلی اختیاری
۲ خروجی CSV                →  ۸ شیت تفکیک + ستون پلتفرم
```

داده قدیمی دیوار مهاجرت می‌شود (`platform='divar'`). رفتار دیوار اگر شیپور خاموش باشد باید مثل ۲.۱.۲۵ بماند.

## ۳) پلتفرم‌های جدید

### ۳.۱ سوییچ

تنظیمات + داشبورد: `☑ دیوار  ☑ شیپور  ☑ رینگ`  
خاموش = هیچ جستجو، شماره، چت، استعلام آن سایت. هر سه خاموش → اسکن شروع نشود.

روی هر پایش (آپشن اضافه): تیک ارثی یا اختصاصی «فقط این سایت‌ها».

### ۳.۲ اکانت / پروفایل (UI عوض اساسی نشود)

یک پوشه Chromium. با «افزودن پروفایل» سه تب:

- دیوار `/user`
- شیپور `/session`
- رینگ صفحه اصلی (مودال OTP)

سه پیامک جدا. «ذخیره پروفایل» کوکی سه دامنه. روی کارت سه وضعیت لاگین کوچک.

اگر رینگ لاگین نباشد فقط رینگ برای آن اکانت می‌ایستد.

### ۳.۳ کشف آگهی و شماره

| | دیوار | شیپور | رینگ |
|---|---|---|---|
| جستجو | HTML `/s/{شهر}/{دسته}?q=` | همان شکل، زنده تأیید شد | Chromium / Flutter |
| آگهی | `/v/{slug}/{token}` | `/v/{slug}-{id}.html` | `/a/{id}` |
| قیمت لیست | تومان/ریال | تومان یا توافقی | DOM |
| وضعیت کالا | واژگان | فیلد **وضعیت کالا** زنده | واژگان + DOM |
| شماره | API v2 | کلیک «نمایش کامل» در پروفایل | پنل تماس بعد از OTP؛ ممکن است فقط چت |
| چت | داخل دیوار | «چت با {نام}» + چیپ «قیمت چنده؟» | مسیر اصلی |

کلید یکتا: `(platform, native_id)`.

### ۳.۴ دسته — یک درخت، کامل‌تر

یک دراپ‌داون. اسلاگ شیپور/رینگ پشت صحنه (`light`↔`car`، `mobile-phones`↔`mobile-tablet`، …).  
اضافه نسبت به امروز: زمین، اجاره کوتاه، کلاسیک، سیم‌کارت، دوربین، فرش، سرمایش، لوازم برقی خانه، ظروف، دکوراسیون، و گروه کامل خدمات/استخدام/شخصی/سرگرمی/صنعتی.

## ۴) شکارچی قیمت — کامل و آپشن‌ها

VIP فعلی فیلتر بودجه است. شکارچی نسخه ۳ این است:

> «آیفون ۱۳ تهران ۳۲ م؛ میانه ۴۸ م؛ −۳۳٪؛ نو؛ شیپور؛ ۲ دقیقه پیش.»

### ۴.۱ لوله (اجباری)

1. خریدار → حذف  
2. معیوب (فیلد شیپور + واژگان) → سطل معیوب، ویژه نه  
3. نوع قیمت: نقد / توافقی / `۱۰۰۰` جای‌نگهدار / اقساط / معاوضه  
4. کف دسته (موبایل زیر ۵۰۰ هزار بدون معیوب = جای‌نگهدار)  
5. امتیاز فقط روی نقد سالم نسبت به میانه ۷۲ساعته همان پایش  
6. مسیر تماس  
7. اگر قیمت نامعلوم → استعلام از چت یا پیامک → فهم جواب → برگشت به ۵  

سطوح: بازار / مناسب (۱۰–۲۲٪) / خیلی‌مناسب (>۲۲٪ تا ۴۵٪) / مشکوک (>۴۵٪ بدون هشدار).

میانه از آگهی **نقد سالم** ساخته می‌شود؛ معیوب و ۱۰۰۰ داخل میانه نروند.

### ۴.۲ آپشن‌های شکار (همه در تنظیمات / کارت پایش)

| آپشن | پیش‌فرض | چرا |
|---|---|---|
| تیک شکارچی روی پایش | خاموش | با فیلتر بودجه قاطی نشود |
| هشدار «مناسب» | روشن | |
| هشدار «خیلی مناسب» | روشن | صدای فعلی VIP |
| آستانه مناسب / خیلی‌مناسب / مشکوک٪ | ۲۲ / ۴۵ | خودرو پراکنده‌تر است — قابل ویرایش |
| پنجره میانه | ۷۲ ساعت یا ۳۰ نمونه | |
| فاصله اسکن فقط پایش شکار | ۶۰–۹۰ ثانیه | پایش بازاریابی همان ۳۰۰ ث |
| رد خریدار | همیشه | غیرقابل خاموش |
| رد توافقی از شکار | روشن | می‌رود استعلام |
| رد اقساط / معاوضه | روشن | |
| رد فروشگاه / ویترین | خاموش | تیک «فقط آگهی شخصی» |
| رد «نیازمند تعمیر» | روشن | سطل معیوب جدا |
| فقط وضعیت نو / درحدنو | خاموش | برای نوسان‌گیر موبایل |
| حداقل درصد تخفیف دستی | خالی | اگر پر شود جای آستانه پیش‌فرض |
| سقف قیمت خرید (`max_buy`) | خالی | حتی شکار بالای بودجه هشدار ندهد |
| سخت‌گیری عنوان | روشن روی شکار | «آیفون ۱۳» باید در عنوان باشد |
| تکراری بین سایت‌ها | روشن | یک شکار، دو لینک |
| رد آگهی تبلیغ/تابلو/ویترین | خاموش | آپشن جدا |
| استعلام خودکار جای‌نگهدار | نیمه‌پیش‌فرض: صف استعلام | تیک ارسال خودکار جدا |
| کانال استعلام | چت اگر هست وگرنه پیامک | نه هر دو با هم |
| سکوت شب شکار (مثلاً ۰–۷) | خاموش | آپشن |

هشدار تلگرام ویژه فقط بعد از نقد سالم غیرمعیوب — نه بعد از دیدن `۱۰۰۰`.

### ۴.۳ استعلام قیمت (بخش ویژه)

قالب جدا از بازاریابی. چیپ سایت مقدم است.

پاسخ → قاعده (و مدل محلی اگر مبهم) → عدد نقد / معیوب / فروخته / بیعانه.

فقط بعد از عدد نقد، شکارچی تصمیم ویژه می‌گیرد.

## ۵) پیام خودکار — چت و پیامک

خواست محصول ۳ (حتی اگر کد ۲.۱.۲۵ چت را نیمه دارد):

| شرط | عمل |
|---|---|
| شماره `found` + تیک پیامک | قالب sms |
| فقط چت + تیک چت خودکار | قالب chat روی همان پلتفرم |
| کلاس inquire + تیک استعلام | قالب inquire یا چیپ |

سقف جدا: چت ساعت/روز/پلتفرم، فاصله ≥ ۹۰ث، یک پیام per آگهی، `{title}` اجباری.

ChatWorker از Chromium همان پروفایل برای دیوار، شیپور، رینگ. قفل پروفایل تا دو تب با هم نفرستند.

صندوق پاسخ:

- چت: خواندن نخ همان پروفایل  
- پیامک: پولینگ Receive ملی‌پیامک (وب‌هوک به ویندوز محلی نمی‌خورد)

آپشن‌های پیام (اضافه):

| آپشن | پیش‌فرض |
|---|---|
| `chat_auto_on` | خاموش |
| `sms_auto_on_new` | همان فعلی |
| چت خودکار per-platform | ارث از سوییچ |
| ساعت سکوت ارسال (مثلاً ۲۳–۸) | روشن پیشنهادی |
| هرگز به یک شماره/فروشنده دوباره | روشن |
| لیست سیاه کلمه در عنوان | خالی |
| حداکثر چت در روز | ۴۰/اکانت |
| تست ارسال به خودتان | دکمه در تنظیمات |

## ۶) درک پاسخ (بدون API پولی اجباری)

1. **قاعده داخل سورس** (رایگان، با کد یکی): عدد، معیوب، فروخته، بیعانه، سلام خالی.  
2. **مدل محلی اختیاری** (~۱٫۵ GB) مثل Chromium — نه داخل گیت.  
3. **کلید ابری مشتری** اگر خودش گذاشت — نه چرخش کلید رایگان برنامه.

مدل پیام بازاریابی بعدی را نمی‌فرستد. فقط intent می‌دهد.

## ۷) خروجی، پنل، داشبورد

شیت/فایل:

1. شکار خیلی‌مناسب  
2. شکار مناسب  
3. معیوب  
4. استعلام باز  
5. استعلام پاسخ  
6. شماره‌دار  
7. فقط‌چت

ستون‌ها: پلتفرم، قیمت اعلامی، نوع قیمت، قیمت واقعی، وضعیت کالا، سطح شکار، کانال ارسال، intent پاسخ، شماره، لینک، زمان کشف.

فیلتر پنل سرنخ همان سطل‌ها + پلتفرم.

داشبورد اضافه:

- KPI جدا دیوار/شیپور/رینگ  
- تعداد شکار امروز / معیوب / استعلام باز  
- وضعیت لاگین سه سایت روی هر اکانت  
- میانه پایش‌های شکارچی (گرم شده یا نه)

تب جدید لازم نیست؛ کارت شکار روی همان «کلمات» و فیلتر روی «سرنخ‌ها».

## ۸) آپشن‌های سیستمی دیگر که نسخه فروشی باید داشته باشد

این‌ها در ۲.۱.۲۵ نیستند و در ۳.۰ باید باشند یا تیک تنظیمات بگیرند:

| آپشن | توضیح |
|---|---|
| عدم تماس تکراری | هش شماره + شناسه فروشنده؛ دومین آگهی همان نفر پیامک/چت نگیرد |
| تکراری سه‌سایت | عنوان نرمال + قیمت نزدیک → یک کارت، چند لینک |
| پاکسازی آگهی حذف‌شده | 404 → `removed`؛ از صف پیام خارج |
| پشتیبان/بازیابی | یک دکمه خروجی پوشه داده (`DivarMarketing`) |
| حالت آزمایش (dry-run) | جستجو و شکار واقعی؛ ارسال چت/پیامک زده نشود — برای دمو فروش |
| توقف خودکار پلتفرم | ۳ کپچا پشت‌سرهم همان سایت → آن سوییچ برای آن اکانت خاموش تا آزادسازی |
| گسترش شهر | شهرهای شمال که شیپور قوی است (بابل، قائم‌شهر، …) به جدول شهر |
| مترادف کلمه | «آیفون ۱۳، iPhone 13» روی یک پایش |
| سقف کشف per پایش در ساعت | تا یک دسته کل ایران صف را نترکاند |
| یادداشت روی سرنخ | دستی |
| خروجی بازه تاریخی | از–تا در اکسل |
| نمایش میانه روی کارت پایش | «بازار این پایش: ۴۸ م · ۳۰ نمونه» |
| هشدار «شکارچی گرم نشده» | تا نمونه کافی، ویژه نسبی ساخته نشود |

لایسنس/اشتراک اگر می‌فروشید: قفل قابلیت در تنظیمات، داده محلی. در ۳.۰ می‌تواند فقط هوک خالی باشد تا هسته اول درست کار کند.

## ۹) آنچه در پنل عوض می‌شود (کم، حساب‌شده)

- اکانت‌ها: سه تب لاگین + سه وضعیت؛ دکمه «باز کردن» می‌تواند دیوار یا شیپور یا رینگ باشد  
- کلمات: دسته کامل‌تر؛ تیک شکارچی؛ آپشن‌های رد (فروشگاه، اقساط، …) در یک بلوک جمع‌شو  
- تنظیمات: سوییچ سه پلتفرم؛ تیک چت خودکار؛ سقف چت؛ سکوت شب؛ آستانه‌های٪ شکار؛ دانلود مدل درک متن (اختیاری)  
- سرنخ‌ها: فیلتر پلتفرم / شکار / معیوب / استعلام / پاسخ‌داده  
- پیام‌ها: سه قالب (چت، پیامک، استعلام)  
- داشبورد: KPI سه سایت + شکار امروز

## ۱۰) تغییرات فنی کد (برای وقتی شروع شود)

- پنل: سوییچ، تیک‌ها، فیلترها

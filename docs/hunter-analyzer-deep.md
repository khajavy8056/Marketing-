# بخش شکارچی — آنالیزور قیمت پیشرفته با مدل

## دو بخش سیستم

### بخش ۱) پیدا کردن شماره تلفن (پایه)
- کاربر دسته یا کلمه کلیدی تعیین می‌کند (مثلاً دسته `light` خودرو یا کلمه `پراید`)
- پلتفرم‌ها: دیوار / شیپور / رینگ — هر کدام تیک جدا در تنظیمات → اگر هر سه فعال، هر سه جستجو می‌شوند
- `monitor._search_platforms()` → `enabled_from_settings()` → اگر `platform_divar=True` → `anon.search()` دیوار، اگر `sheypoor=True` → `sheypoor.search()`، اگر `ring=True` → `ring.search()`
- هر آگهی جدید → `consider_new_lead()` → صف `pending_phone`
- کارگر شماره: `get_contact()` → دیوار API دو مرحله‌ای (contact_uuid + contact_info_v2) + شیپور/رینگ via browser reveal (CDP کلیک «نمایش شماره» در Chromium پروفایل جدا)
- تفکیک درست: `classify_listing_html` → `found` (0912...) / `hidden` (صریحاً «فقط چت») / `removed` (حذف شده) / `error` (خطا → در صف می‌ماند، دوباره تلاش)
- ارسال پیامک: اگر `sms_auto_on_new=True` و ملی‌پیامک تنظیم → `maybe_send_for_lead()` با قالب `{title} {city} {price} {greeting} {closing}`
- چت: اگر شماره ندارد (`hidden`) و `chat_auto_on_new=True` → `compose_chat()` با متغیر `{title}` اجباری + `greeting/closing` گردونه هر بار متفاوت → متن‌ها یکسان نیستند (ضد اسپم)
- مثال: آگهی «پراید 1399» در تهران → پیامک: «سلام، وقت بخیر 🌹 آگهی پراید 1399 در تهران — ۳۰۰ میلیون تومان دیدم. ممنون از وقتی که می‌گذارید 🙏» — هر بار greeting/closing متفاوت

### بخش ۲) شکارچی — بخش اصلی با هوش مصنوعی

اینجا مدل درگیر می‌شود — آنالیزور قیمت.

#### مشکل قدیمی
نسخه اول فقط قیمت کاربر را می‌گرفت — مثلاً ۳۰۰ میلیون برای پراید — ولی نمی‌فهمید این پراید چه وضعیتی دارد: صفر است یا ۱۰۰km؟ رنگ دارد یا بی‌رنگ؟ شاسی سالم است یا ضربه؟

#### راه‌حل جدید — آنالیزور چند لایه

**۱) میانه بازار:**
- `collect_samples(keyword, city, platform)` → فقط نقد سالم (نه معیوب، نه جای‌نگهدار، نه خریدار) → `median_of()` حداقل ۳ نمونه
- مثلاً پراید در تهران میانه ۳۲۰ میلیون

**۲) افت وضعیت — تحقیق بازار ایران ۱۴۰۳:**
برای هر دسته خانواده جدا (vehicle, phone, laptop, appliance, generic):

- **خودرو** (دقیق‌ترین):
  - رنگ: یک لکه کوچک -۲.۵٪، یک قطعه -۴٪، دو قطعه -۷٪، چند قطعه -۱۱٪، دوررنگ -۱۴٪، تمام‌رنگ -۱۹٪، سقف رنگ -۱۲٪
  - شاسی: ضربه جزئی -۱۲٪، ضربه/رنگ -۲۰٪، ستون ضربه -۲۸٪
  - تصادف: جزئی -۶٪، چپی -۱۸٪، ایربگ -۲۴٪
  - فنی: واشر -۶٪، موتور -۱۲٪، تعویض موتور -۱۸٪، گیربکس -۲۰٪
  - کارکرد: هر ۲۰ هزار km بالای نرمال ۱٪ افت، صفر خشک +۳٪ گران‌تر از ۱۰۰km → پس ۱۰۰km با قیمت مناسب هنوز شکار است
  - تاکسی -۱۳٪، بیمه ندارد -۲.۵٪، لاستیک نو +۱.۵٪
  - سقف جمع افت -۴۵٪ تا +۵٪

- **موبایل**:
  - آکبند ۰٪، در حد نو -۳٪، خط و خش -۷٪، ترک -۲۲٪، بدون کارتن -۶٪، رجیستر نشده -۱۶٪، باتری ۸۵٪ -۴٪، باتری زیر ۸۰٪ -۱۱٪، آب‌خوردگی -۲۶٪، تعمیر برد -۳۲٪، فیس آیدی خراب -۱۴٪

- **لپ‌تاپ**: HDD به‌جای SSD -۱۱٪، رم ۴ -۷٪، صفحه لکه -۱۴٪، باتری ضعیف -۸٪

- **لوازم خانگی**: کارکرده -۸٪، بدون کارتن -۴٪، تعمیری -۲۲٪

**۳) کارکرد و سال — مثال ۱۰۰km vs صفر:**
- `mileage_adjustment(mileage, year, km_per_year)`:
  - ۰km → +۳٪ (صفر خشک گران‌تر)
  - ۱۰۰km → +۲.۵٪ (هنوز خیلی کم، نزدیک صفر)
  - ۲۰ هزار km نرمال برای ۱ سال → اگر ۱۰۰km با ۱ سال، کمتر از نرمال → +۱٪
  - ۱۰۰ هزار km برای ۵ سال (۱۳۹۹) → نرمال ۱۰۰k → ۰٪
  - ۱۳۰ هزار km برای ۵ سال → ۳۰k اضافه → -۱.۵٪
  - بالای ۲۰۰k → -۹٪
- پس پراید صفر ۳۲۰m، پراید ۱۰۰km با همان وضعیت ۳۱۰m منصفانه است — اگر ۲۵۰m باشد ۱۹٪ زیر منصفانه → great

**۴) مثال دوررنگ با قیمت مناسب هنوز شکار:**
- میانه پراید ۳۲۰m
- دوررنگ -۱۴٪ + کارکرد ۱۰۰km +۰٪ = ارزش منصفانه ۲۷۵m
- اگر قیمت ۲۰۰m → تخفیف (۲۷۵-۲۰۰)/۲۷۵=۲۷٪ → great (آستانه great ۱۸٪)
- حتی دوررنگ اگر خیلی ارزان باشد شکار محسوب می‌شود — این دقیقاً چیزی است که کاسب حرفه‌ای می‌خواهد

**۵) تنظیمات پیشرفته — درصد دقیق + آپشن جدید:**
- UI: تب کلمات → شکارچی → تنظیمات پیشرفته → دیالوگ هشدار تخصصی (⚠️ این بخش تخصصی است، یک کاسب حرفه‌ای پر کرده)
- کاربر می‌تواند:
  - آستانه good/great/suspicious را سفت کند (مثلاً good ۱۲٪، great ۲۲٪، مشکوک ۴۵٪)
  - km_per_year را تغییر دهد (مثلاً ۱۵ هزار برای کم‌کارکرد)
  - dealer_mode: جای‌خالی شاسی/رنگ را حتماً بپرس
  - درصد هر افت را تغییر دهد (مثلاً paint_full از -۱۴٪ به -۱۰٪ اگر خودتان رنگ را کم‌اهمیت می‌دانید)
  - **آپشن جدید اضافه کند**: کلید انگلیسی + برچسب فارسی + درصد افت + کلمات کلیدی + سوال
    - مثلاً «لاستیک ساییده» -۳٪ با کلمات «لاستیک ساییده, لاستیک 20 درصد» → سوال «لاستیک چند درصد است؟»
    - مثلاً «باتری تعویض» -۸٪، «کف‌خواب» -۵٪، «گلس شکسته» -۶٪
- ذخیره: `hunter_adv` JSON در جدول keywords → `custom_adjustments` لیست → `merge_overrides()` → اضافه به پروفایل
- API: `GET /api/hunter-profile?keyword=&category=` → research_note + warning + adjustments با research توضیح + custom
- `POST /api/keywords/{id}/hunter-adv` → ذخیره

**۶) مدل چطور درگیر می‌شود:**
- `nlu_engine.py` → `evaluate_hunter(price, samples, extra, text, category, keyword)` → `default_profile()` + `merge_overrides(hunter_adv)` + `evaluate()` با mileage_adjustment
- اگر جای‌خالی باشد (year, mileage, chassis, paint) و dealer_mode → `pending` → `hunter_pending` event → `build_questions()` → `inquiry_prompt()` → `infer_json()` با مدل محلی (Qwen) → متن مودبانه با سوال‌های دسته → SMS اگر شماره هست وگرنه چت → `inquiry_sent`
- پاسخ می‌آید → `inbox.ingest_chat/sms` → `analyze_for_platform()` با حافظه → `fill_from_reply()` → استخراج year, mileage, chassis, paint, price از پاسخ → `evaluate()` دوباره → `hunter_evaluated` → تصمیم نهایی شکار

**۷) هشدار اولیه تخصصی:**
- دیالوگ اول: «⚠️ تنظیمات تخصصی شکارچی — بخش مهم» با warn-box:
  - این بخش تخصصی است — یک کاسب حرفه‌ای بر اساس تحقیق بازار ایران ۱۴۰۳ پر کرده
  - مثال 100km vs صفر و دوررنگ با قیمت مناسب هنوز شکار
  - اگر بلد نیستید دست نزنید، اگر کاسبید سفت‌تر کنید و آپشن جدید اضافه کنید

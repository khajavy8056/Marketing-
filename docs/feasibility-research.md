# 🔍 تحقیق امکان‌سنجی: سیستم جستجوی کلمه‌کلیدی در دیوار و ارسال پیام به آگهی‌دهندگان

> وضعیت: فاز تحقیق — پیش از پیاده‌سازی

## 🎯 خلاصه اجرایی (Executive Summary)

**سؤال:** آیا می‌شود سیستمی ساخت که با یک کلمه‌کلیدی، آگهی‌های دیوار را پیدا کند، شمارش کند و به صاحبان آن‌ها پیام داد؟

**پاسخ کوتاه:**

| قابلیت | امکان‌پذیری | مسیر |
|---|---|---|
| جستجوی کلمه‌کلیدی و گرفتن لیست آگهی‌ها | ✅ بله، کاملاً شدنی | API غیررسمی وب دیوار (بدون احراز هویت) |
| شمارش تعداد آگهی‌های یک کلمه‌کلیدی | ✅ بله | همان API + صفحه‌بندی |
| گرفتن جزئیات هر آگهی (عنوان، توضیحات، قیمت، شهر) | ✅ بله | همان API |
| گرفتن شماره تلفن آگهی‌دهنده | ⚠️ فقط برخی آگهی‌ها | اگر آگهی‌دهنده «نمایش شماره» را فعال کرده باشد |
| ارسال خودکار پیام در چت دیوار به افراد دلخواه | ❌ به‌صورت رسمی خیر / ⚠️ به‌صورت غیررسمی پرریسک | جزئیات پایین ⬇️ |
| ارسال پیامک به شماره‌های استخراج‌شده | ⚠️ فنی‌اً ممکن، حقوقی‌اً محدود | پنل پیامک تبلیغاتی |

**نتیجه کلی:** بخش «کاوش بازار» (جستجو، شمارش، مانیتورینگ آگهی‌ها و ساخت دیتابیس سرنخ/Lead) **کاملاً شدنی و کم‌ریسک** است. بخش «ارسال پیام خودکار» گلوگاه اصلی است — مسیر رسمیِ دیوار فقط با تأیید کسب‌وکار و رضایت کاربر کار می‌کند و مسیر غیررسمی خطر مسدود شدن اکانت دارد.

## 🗺️ سه مسیر ممکن

### مسیر A — رسمی: پلتفرم «کنار دیوار» (Kenar)

دیوار یک پلتفرم توسعه‌دهنده رسمی به نام **کنار** دارد (پنل مدیریت: `my.divar.ir` — مستندات: `divar-ir.github.io/kenar-docs`) که APIهای عمومی زیر را ارائه می‌دهد. احراز هویت با هدر `X-API-Key` که از پنل کنار می‌گیرید.

| اندپوینت | متد | مجوز API Key | کاربرد |
|---|---|---|---|
| `open-api.divar.ir/v2/open-platform/finder/post` | POST | `SEARCH_POST` | جستجوی آگهی‌ها با فیلتر (دسته، شهر، محله، محدوده قیمت/متراژ/سال و…) |
| `open-api.divar.ir/v1/open-platform/finder/post/:token` | GET | `GET_POST` | جزئیات عمومی **هر** آگهی منتشرشده (نه فقط آگهی‌های خودتان) |
| `open-api.divar.ir/v1/open-platform/chat/bot/conversations/:id/messages` | POST | `CHAT_BOT_SEND_MESSAGE` + اسکوپ OAuth `CHAT_BOT_USER_MESSAGE_SEND` | ارسال پیام از چت‌بات شما به یک مکالمه/کاربر |
| `open-api.divar.ir/v1/open-platform/chat/conversations/:id/messages` | POST | — | ارسال پیام به مکالمه (در صورت نبودِ مکالمه، خودکار ساخته می‌شود) |
| Finder → `get-user-id-by-phone` | — | — | یافتن شناسه کاربر با شماره تلفن (برای CRM) |

**نکات حیاتی مسیر رسمی:**

1. ⚠️ **در مستندات رسمی جستجو، فیلد «متن آزاد / کلمه‌کلیدی» دیده نمی‌شود** — فقط فیلترهای ساختاریافته (دسته‌بندی، شهر، برند/مدل، بازه قیمت و…). یعنی جستجوی کلمه‌کلیدی آزاد باید از تیم کنار پرسیده شود یا با فیلترها شبیه‌سازی شود.
2. 🔒 **ارسال پیام چت‌بات فقط برای کاربرانی که با اپ شما OAuth کرده‌اند کار می‌کند** (user_id باید با «شناسه مبهم‌شده کاربر احرازهویت‌شده» مطابقت داشته باشد). یعنی **پیام سرد (Cold Message) به کاربر دلخواه از مسیر رسمی ممکن نیست** — کاربر باید قبلاً با شما تعامل داشته باشد.
3. 📋 **قبل از توسعه باید تیکت پشتیبانی ساخت و ایده کسب‌وکار را با تیم کنار هم‌سو کرد** (این هشدار در بالای خود مستندات آمده). یک ابزار «اسپم بازاریابی» تقریباً قطعاً تأیید نمی‌شود؛ اما ابزارهایی مثل پاسخ‌گوی خودکار به چتِ آگهی‌های خودتان، افزونه خدمت، ابزار مدیریت آگهی و… دقیقاً موردنیاز آن‌هاست.
4. SDK رسمی: [`divar-ir/kenar-api`](https://github.com/divar-ir/kenar-api) (پایتون) و [`divar-ir/kenar-sdk-javascript`](https://github.com/divar-ir/kenar-sdk-javascript).

### مسیر B — غیررسمی: API داخلی وب/اپ دیوار

سایت دیوار خودش از این اندپوینت‌ها استفاده می‌کند و ابزارهای متن‌باز (مثل پکیج پایتون [`divar`](https://pypi.org/project/divar/) روی PyPI و اسکرپر [`amirh0ss3in/divar`](https://github.com/amirh0ss3in/divar)) سال‌هاست از آن‌ها استفاده می‌کنند:

| اندپوینت | توضیح |
|---|---|
| `GET api.divar.ir/v8/web-search/{شهر}/{دسته‌بندی}?q=کلمه‌کلیدی` | **جستجوی کلمه‌کلیدی** بدون لاگین — خروجی JSON شامل ویجت‌های آگهی + توکن هر آگهی + صفحه‌بندی |
| `GET api.divar.ir/v8/post/{token}` | جزئیات کامل آگهی (عنوان، توضیحات، قیمت، موقعیت، زمان) |
| اندپوینت اطلاعات تماس | معمولاً به نشست لاگین‌شده نیاز دارد؛ شماره فقط وقتی در دسترس است که آگهی‌دهنده نمایش عمومی شماره را فعال کرده باشد |

**نکات مسیر غیررسمی:**

1. ✅ پکیج آماده `divar` در PyPI همین الان دارد: `Search(query='iPhone 13', cities=[1,3,4])` — جستجوی کلمه‌کلیدی در شهرهای مشخص. کدهای شهر: تهران=۱، کرج=۲، مشهد=۳، اصفهان=۴ و…
2. 🌍 **محدودیت جغرافیایی:** سرورهای دیوار عموماً فقط از IP ایران پاسخ می‌دهند. (در تست از سرور خارجی، اتصال اصلاً برقرار نشد.) پس اجرای سیستم باید روی سرور داخل ایران یا با پروکسی ایران باشد.
3. 📦 بدون مستندات و قرارداد رسمی — ممکن است هر زمان بدون اطلاع تغییر کنند → کد باید ماژولار و قابل تعمیر باشد.
4. ⚖️ نقض شرایط استفاده دیوار (دسترسی خودکار بدون مجوز) → ریسک بلاک شدن IP. برای «خواندن» آگهی‌های عمومی معمولاً واکنش شدیدی نمی‌بینید، ولی **برای ارسال پیام خودکار باید با اکانت واقعی لاگین کنید (ورود با کد پیامکی) و دیوار ارسال انبوه خودکار را به‌سرعت شناسایی و اکانت را مسدود می‌کند.**

### مسیر C — ترکیبی (پیشنهادی ✅)

- **کشف سرنخ (Lead Discovery):** با API غیررسمی، کلمه‌کلیدی‌ها را دوره‌ای جستجو کن → آگهی‌های جدید را در دیتابیس ذخیره کن → داشبورد شمارش و ترند.
- **تماس:**
  - شماره‌دارها → لیست تماس/پیامک برای تیم فروش (تماس انسانی مؤثرترین و کم‌ریسک‌ترین است).
  - بقیه → پیام چت به‌صورت **نیمه‌خودکار**: سیستم لیست «کلیک و پیام آماده» تولید کند و انسان با یک کلیک ارسال کند (پیام اول از اکانت واقعی خودتان).
  - مسیر بلندمدتِ بدون ریسک: ثبت‌نام در کنار و ساخت افزونه/چت‌باتی که آگهی‌دهنده خودشOpt-in کند.

## 🏗️ معماری پیشنهادی سیستم (فاز ۲)

```
┌────────────────────────────────────────────────────────┐
│                   داشبورد (وب)                          │
│   مدیریت کلمه‌کلیدی‌ها · شمارش · ترند · لیست سرنخ‌ها      │
└────────────────────────┬───────────────────────────────┘
                         │
┌────────────────────────▼───────────────────────────────┐
│                   API سیستم (FastAPI)                   │
└───┬──────────────────┬─────────────────┬───────────────┘
    │                  │                 │
┌───▼──────┐   ┌──────▼───────┐  ┌──────▼─────────┐
│ جمع‌آور   │   │  دیتابیس     │  │ ماژول تماس     │
│ (Worker) │──▶│ (SQLite/PG)  │◀─│ پیام آماده +   │
│ جستجوی   │   │ آگهی‌ها،      │  │ لینک چت دیوار │
│ دوره‌ای   │   │ سرنخ‌ها،      │  │ + صف پیامک    │
│ دیوار    │   │ وضعیت تماس   │  │ (اختیاری)     │
└──────────┘   └──────────────┘  └────────────────┘
```

**جریان کار (Lead Workflow):**
1. اپراتور کلمه‌کلیدی + شهر + دسته را تعریف می‌کند (مثلاً «تدریس خصوصی» در تهران).
2. Worker هر X دقیقه جستجو می‌زند → آگهی‌های جدید = **سرنخ جدید** (وضعیت: `new`).
3. داشبورد: شمارش کل، نمودار روند، لیست سرنخ‌ها با فیلتر.
4. اپراتور سرنخ را باز می‌کند → دکمه «باز کردن چت دیوار» (`https://divar.ir/v/{token}` یا لینک `divar://`) + متن پیشنهادی آماده → ارسال دستی.
5. وضعیت سرنخ به `contacted / replied / converted` تغییر می‌کند → گزارش نرخ تبدیل.

**غیرتکراری‌سازی (Dedup):** توکن آگهی به‌عنوان کلید یکتا + هش توضیحات برای تشخیص آگهی تکراریِ کاربر.

## ⚖️ ریسک‌ها و ملاحظات

| ریسک | سطح | توضیح |
|---|---|---|
| تغییر API غیررسمی | متوسط | با کپسوله‌کردن لایه دسترسی دیوار مدیریت می‌شود |
| بلاک IP سرور | متوسط | با Rate-limit مؤدبانه (مثلاً حداکثر ۱ درخواست/ثانیه و تاخیر بین صفحات) کاهش می‌یابد |
| بن شدن اکانت دیوار در ارسال خودکار | 🔴 بالا | پیام خودکار انبوه در چت = نقض آشکار قوانین؛ اصلاً توصیه نمی‌شود |
| شکایت اسپم پیامک | متوسط | ارسال انبوه بدون رضایت؛ از خط تبلیغاتیِ معتبر + لینک لغو اشتراک استفاده شود |
| رد شدن درخواست کنار | متوسط | ارائه ایده به‌صورت «ابزار خدمت/مدیریت» نه «اسپم‌کن» |

**ملاحظه حقوقی:** استخراج داده شخصی و تبلیغات تماسی ناخواسته می‌تواند با قانون تجارت الکترونیکی و مقررات حریم خصوصی ایران تعارض داشته باشد. مشورت با مشاور حقوقی برای مقیاس بزرگ توصیه می‌شود.

## 🧪 گام بعدی فوری: راستی‌آزمایی

اسکریپت `scripts/divar_probe.py` آماده شده تا **روی یک سیستم داخل ایران** اجرا شود و ۴ چیز را تست کند:

```bash
python scripts/divar_probe.py --keyword "آپارتمان" --city tehran
python scripts/divar_probe.py --keyword "tutoring" --city tehran --category light  # نمونه
KAPI_KEY=کلید_کنار python scripts/divar_probe.py --official --keyword "آپارتمان"  # تست مسیر رسمی
```

خروجی: وضعیت HTTP هر اندپوینت، تعداد نتایج، چند توکن نمونه، و ساختار فیلدها → مبنای طراحی فاز ۲.

## ✅ جمع‌بندی

- **بخش یافتن/شمارش/دیتابیس:** بله، شدنی — با API غیررسمی سریع شروع می‌شود و اگر نیاز رسمی داشتید به کنار مهاجرت می‌کنید.
- **بخش ارسال پیام:** ارسال «سردِ» خودکار از مسیر رسمی بسته است و از مسیر غیررسمی بن‌ساز است؛ راه درست، **نیمه‌خودکار (human-in-the-loop)** یا **افزونه کنار با Opt-in کاربر** است.
- پیشنهاد: فاز ۲ را با «سیستم مانیتورینگ کلمه‌کلیدی + CRM سرنخ + پیام آماده با ارسال یک‌کلیکی» بسازیم.
